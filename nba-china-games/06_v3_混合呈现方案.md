# v3 方案：真人影像 + 代码画面 + AI 生图，按脚本有机结合

本方案沿用 `04_v2_全代码方案与新脚本.md` 的脚本、旁白和配乐思路，只改「每个镜头用什么形式呈现」。`05_制作规范` 里「人物不写实」那一条作废：**凡是涉及具体球员的画面，一律用真实影像**，再做二次加工。

## 一、分工原则

| 形式 | 负责什么 | 不做什么 |
| --- | --- | --- |
| **真人影像**（NBA 官方素材） | 所有具体球员的动作、表情、现场氛围 | 不长时间原样播放；每段都要经过变速、调色或包装 |
| **代码画面**（HTML/Canvas/WebGL） | 年份、地图、计分牌、票根、标尺、数据、字幕、转场、片头片尾 | 不再画真人（线稿、3D 人物、剪影都已试过，效果不行） |
| **AI 生图**（百炼 qwen-image / wan2.7-image） | 没有影像的年代和场景：1979 年北京街景、1989 年央视传达室、录像带、胡同里的篮球架 | 不生成任何真实球员或斯特恩的脸 |

真人影像和代码画面不是简单地一段接一段，而是**互相嵌套**：

- **代码包裹真人**：真人片段放进代码画的老电视、票根窗口、分屏格子里。
- **代码叠在真人上**：身高标尺、名字、数据跟着球员移动。用人物遮罩可以让大字压在人身后。
- **转场互相咬合**：代码战术板上的跑位线终点，正好接上真人扣篮的起跳点；票根上的火箭徽标，直接放大成真实球衣上的徽标。

## 四、真人影像的加工手段（「剪映式」工具包）

用开源组件拼成我们自己的工具包，所有效果都读同一份时间轴文件，剪辑点和音乐节拍精确到帧：

| 效果 | 实现 | 状态 |
| --- | --- | --- |
| 变速曲线、AI 慢放 | venhance（RIFE，MIT，Apple 芯片原生）补帧，再按速度曲线取帧 | **已装，已实测**：27 帧补到 108 帧，用时 12 秒，比 ffmpeg 补帧干净得多（无重影） |
| 画质增强 | venhance 内置 Real-ESRGAN（BSD），720p 素材放大到 1080p 以上 | 已装 |
| 自动切镜头 | PySceneDetect（BSD），把官方合集拆成单个镜头，方便挑选 | 已装 |
| 音乐卡点 | librosa（ISC）测节拍、小节和能量，生成节拍表 | 已装 |
| 人物遮罩 | YOLO11 + SAM 2.1，用于「字压人后」、主体追光、按人物轮廓转场 | 已装，已实测 |
| 智能重构图 | 用人物框做平滑跟踪，在竖版和横版之间自动裁切 | 待写 |
| 调色和年代滤镜 | 自写调色（S 曲线、青橙分离、泛光、光条、颗粒），再加 CRT、胶片、VHS 等年代滤镜，对应 04 号文件里的年代配色 | 调色已写，滤镜待写 |
| 冲击类效果 | 闪白、推镜、抖动、RGB 分离、径向模糊、定格放大 | 闪白和推镜已写，其余待写 |
| 转场 | gl-transitions（MIT）的 GLSL 转场，放进现有 WebGL 渲染管线；或者用 ffmpeg 的 xfade | 待接 |
| 包装窗口 | 老电视、票根、分屏、画中画，由代码场景直接把视频当作贴图 | 待写 |

**看过但不用的**：

- **Remotion**：公司超过 3 人就要买商业授权。
- **editly**：原生依赖在新版 Node 上装不上。
- **Revideo**（MIT）可用，但它做的事我们现有的 HTML 渲染管线已经能做。
- **pyJianYingDraft**（Apache-2.0）能用 Python 生成剪映草稿，适合最后把工程交给贵方剪辑师在剪映里微调。限制：只有 Windows 上的旧版剪映能自动导出；剪映自带的特效和音乐商用授权需要单独确认。可作为交付选项。

## 五、合规要点

- 真人影像只取 NBA 官方账号发布的内容。其中如果含转播机构的画面（央视、腾讯等的台标或解说），需要贵方法务确认 NBA 是否有权二次使用。
- AI 生图只生成无人物或背影的泛指场景，不生成真实人物的脸。
- 第三幕依旧只讲「暂停」，不讲原因。
