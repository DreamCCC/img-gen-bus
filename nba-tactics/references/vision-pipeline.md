# 视觉管线：看懂回合、跟踪、标定、蒙版、慢放

## 0. 片段结构

单回合片段一般是：高机位全景 8–12 秒，接着切近景回放 1.5–3 秒。只用全景段。用场景检测找切点，后面所有工具的 `--end` 都截在切点前：

```bash
ffmpeg -i raw/e453_pullup.mp4 -vf "scdet=threshold=12,metadata=print" -f null - 2>&1 | grep lavfi.scd.time
```

拆原始帧（渲染器从这里取帧，`0000.jpg` 就是第 0 帧）：

```bash
mkdir -p work/e453/fr/orig && ffmpeg -v error -i raw/e453_pullup.mp4 -q:v 2 -start_number 0 work/e453/fr/orig/%04d.jpg
```

## 1. 看懂回合（最花时间，也最不能省）

1. 先出每 0.5 秒一格的接触表，看懂整体：谁持球、往哪传、谁投。
2. 缩略图看不清号码和球。**改成按原分辨率裁出局部，每张拼 4 帧。** 一大张网格图缩下来什么都读不出。
3. 写出传球链和关键帧号：每次传球的出手帧和接球帧、突破起止帧、起跳帧、出手帧、球进框帧、扑防人起跳帧。
4. 核对 PBP：画面上看起来是"自己运球打进"，PBP 却记了助攻，说明前面有一次传球你还没找到，继续往前看。
5. 方位描述用画面上的相对位置（弧顶、右翼、罚球线），不要随便说"强侧/弱侧""左翼/右翼"，以免和进攻方向混淆。

## 2. 跟踪和认人

```bash
python tools/track.py raw/e453_pullup.mp4 work/e453 --end 11.8 --every 15
```

YOLO 检测人 + BoT-SORT 跟踪；按脚下是不是木地板或油漆区颜色，过滤掉看台观众；按球衣色相粗分两队。输出 `tracks.json`，以及 `ids/` 下每 15 帧一张带编号的预览图。

**跟踪编号会断，也会串号。** 一个 12 秒的回合出现了 102 个编号，比场上 10 个人多得多。不要试图修好跟踪器，直接人工指认：

`eNNN_players.json`：

```json
{"key": "KD", "name": "杜兰特", "num": "7", "team": "HOU",
 "ids": [[52, 14, 185], [52, 201, 260]],
 "manual": [[186, 1452, 876], [190, 1412, 871]],
 "air": [[224, 243]]}
```

- `ids`：`[跟踪编号, 起始帧, 结束帧]`。同一个人换了编号就加一段。同一个编号在某段跳到别人身上，就把那段从区间里切掉。
- `manual`：`[帧, 脚底像素 x, 像素 y]`。串号、被挡住、被下方数据条盖住的帧，人工补脚底点。在 `gridsheet.py` 出的网格图上读坐标。
- `air`：起跳到落地的帧段。这段脚底投影不可信，用两端位置插值。
- `key` 在 EDL 里引用；`team` 决定颜色；`num` 和 `name` 显示在名牌上。

认人的步骤：在 `ids/` 预览图上找到候选编号 → 按原分辨率裁切，看清球衣号码 → 对 `kb_pbs` 名单 → 号码实在看不清时，用换人记录反推当时在场的五人，再结合外形（如长卷发）排除。

然后跑：

```bash
python tools/traj.py work/e453 e453_players.json     # → work/e453/players.json
```

`traj.py` 把每人的编号段拼成一条球场轨迹（英尺）：补 45 帧以内的缺口，再做中值加均值平滑。

## 3. 球场标定（参考帧）

球场坐标：`u` 是距底线的英尺数（向中场为正），`v` 是横向英尺数（0 是篮筐中轴，靠近机位为正）。篮筐中心在 `(5.25, 0)`。

1. 挑一帧禁区四条边都看得见的帧当参考帧，例如 e453 的第 184 帧。
2. 用 `gridsheet.py` 把四个角各放大读点：底线两角是 `(0, ±8)`，罚球线两端是 `(19, ±8)`。角被腿挡住时，用两条线延长求交点。
3. 求 G，然后看核对图：

```bash
python tools/calib.py raw/e453_pullup.mp4 184 "390,695=0,8;643,496=0,-8;1155,794=19,8;1340,565=19,-8" work/calib/G453_184.npy
```

绿线（禁区、限制区弧、罚球圈、三分线）要贴住地板上的实线。三分线贴不上，说明读点错了，不是镜头的问题。

4. 合理性检查：投篮人起跳点离篮筐的距离要和 PBP 的 `shot_distance` 对得上。写好 EDL 后，用 `tools/check_shot.py` 自动比对：e464 算出 25.0 英尺，记录 25.2；e453 算出 11.5 英尺，记录 12.2。差超过 2 英尺时，先查标定读点，再查投篮人的跟踪编号和脚底点。

## 4. 镜头补偿（逐帧）

```bash
python tools/camera.py raw/e453_pullup.mp4 work/e453 --ref 184 --G work/calib/G453_184.npy --end 11
```

在相邻帧上做 ORB 特征匹配求单应，遮掉球员框、右下角记分牌和左上角台标，链式累积到参考帧，再乘 G。输出的 `cam.json` 是每帧像素到球场的映射。

验证：抽 0、60、120、180、240、最后一帧，把场地线投回画面，看有没有漂移。觉得某几帧"偏了"时，先放大原图确认：参考实现里那次怀疑是读图读错了，真正的问题是下方数据条盖住了球员的脚，导致框底不等于脚底。

## 5. 人形蒙版

```bash
python tools/seg.py raw/e453_pullup.mp4 work/e453 --ids <全部用到的跟踪 ID> --start 55 --end 265
```

`yolo11x-seg`（MPS），按和跟踪框的 IoU 配对，输出 `masks/NNNN.npz`。渲染器用它做两件事：时停时只给重点球员上色，以及让地板线被身体挡住。时停帧上某人被遮挡、没配上蒙版时，渲染器会按脚底位置补抠（存到 `masks_extra/`）。报"补蒙版失败"或"脚底偏差 40px 以上"时，要看图确认没有抠错人。

## 6. 4 倍插帧慢放

只对要慢放的帧段做。e453 用的是 95–262 帧：

```bash
cd work/e453 && mkdir -p slow fr/slow
ffmpeg -y -loglevel error -i ../../raw/e453_pullup.mp4 \
  -vf "trim=start_frame=95:end_frame=263,setpts=PTS-STARTPTS,minterpolate=fps=120:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1" \
  -c:v libx264 -crf 10 -preset fast slow/f95_262_x4.mp4
ffmpeg -y -loglevel error -i slow/f95_262_x4.mp4 -q:v 2 -start_number 0 fr/slow/%04d.jpg
```

EDL 里写 `"slow": {"dir": "work/e453/fr/slow", "from": 95, "mul": 4}`。核对：慢放第 4k 帧应该和原片第 95+k 帧一致（差异不到 2 像素）。转播画面本身带运动模糊，快动作插帧也不会明显撕裂。蒙版生成和插帧可以并行跑。

## 7. 球和篮筐

`ball.py`（YOLO 的 sports ball 类别）在转播全景里基本都是误检，只能当参考。传球途中的球位、篮筐位置都人工读：

- `ball`：`[[帧, x, y], ...]`，传球途中每 3 帧一个点，渲染器画光晕拖尾，用镜头补偿换算到当前帧。
- `anchors.rim`：`[帧, x, y]`，出手弧线的终点。

用 `gridsheet.py raw/xxx.mp4 out.jpg 142,145,148,151 --crop x1,y1,x2,y2` 读点，裁切范围小一点才读得准。
