# 用户反馈：被打回的做法和开工前要问清的事

用户原话放在引号里。每条都写了"以后怎么做"。新项目开工前通读一遍，写稿前再读一遍"文稿和内容"一节。

## 用户的偏好（默认按这些来）

- 平台：主做 B 站长视频，有趣的长科普。"其实不需要原定60秒呀，把一个故事讲完"。
- 人设：讲解者"默认什么都知道"，不讲自己的成长过程。
- 观众：假定知识水平不高，"一定要通俗易懂，深入浅出"。
- TTS：只用阿里云百炼。语速默认 1.25 倍。喜欢有力量的男声（`longfei_v3`、龙三叔都选过）；激情程度宁高勿低，"都不够激情，不够调动人的情绪"。
- 画面：真人影像、代码画面、万相生成"有机结合"，按脚本需要选手段。强项是代码画的 3D 示意，但现实题材必须有真实影像补充。
- 版权：用户负责处理版权和授权，素材可以去网上找；我们负责短片段使用、标注出处、标注 AI 生成。
- 用户不能替你核实事实："我无法核实，你自己去网上搜索核实。我个人能力有限"。
- 战术解析：要"让人能直观看到这次进球发生了什么事情，即使没有明显战术"。认可的手法是标重点球员、画传球线、时停、子弹时间、战术板（`nba-tactics/SKILL.md` 的叙事模板）。用户选了不加背景音乐，只用旁白、原声和音效。

## 文稿和内容

这是被打回次数最多的一类。

| 被打回的做法 | 用户原话 | 以后怎么做 |
| --- | --- | --- |
| 书面腔、讲义腔 | "很AI味道""还是有点AI的遣词造句……就像普通人在说话一样，不要高高在上" | 先读 `creator-channel/口播风格指南.md`；写完跑 `ai_lint.py` 和 `style_stat.py` |
| 有信息没看点 | "你这个内容什么也没科普啊，吸引人的地方在哪里" | 每一段都要回答"观众为什么要继续看" |
| 平铺直叙 | "就是内容不太有意思，还是平铺直叙" | 设计情绪的起承转折：悬念、反转、具体场景 |
| 钩子是观众已经知道的事 | "本来现在人就觉得现在考清华北大很难，这个不足以调动情绪" | 钩子要反直觉，或者给一个观众想不到的具体画面 |
| 说法含糊，指代不清 | "越飞越远然后呢？""另外走的是什么路？""往回想一想是怎么往回？" | 每句话都要能独立看懂；"然后呢"要有下文，指代要说清楚 |
| 后半段失控 | "写到中间的时候，感觉就已经看不懂在说什么了……说到某一个话题然后就戛然而止""越到后面越不知道在说什么，观众看的云里雾里" | 问题在大纲，不在句子。先写一行一个问题的大纲给用户确认；每个话题要有结论再转下一个；结尾回收开头的悬念 |
| 标题没讲清楚是什么事 | "感觉没有把事情讲明白""封面、标题、和简介等一定要点明是在讲高考" | 标题和封面直接点出主题，再加悬念 |
| 4:3 封面直接从 16:9 裁 | "4:3封面有点问题" | 每个比例单独排版 |

## 开工前要问清的事

1. 发布平台和时长（默认 B 站长视频）。
2. 素材来源有没有限制（官方素材、TikHub、YouTube、万相），授权由谁处理。
3. 配音音色和语速（默认 1.25 倍）；有没有喜欢的参考 UP 主。
4. BGM 是生成、找流行曲，还是用户提供。
5. 有没有必须出现的画面或事实。
6. 先给大纲和样片，确认后再铺开。
